# Complete pinned automation graphs

[Issue #276](https://git.subcult.tv/subculture-collective/overlaid/issues/276) supplies the pure graph-resolution prerequisite for Phase 3 E2. `engine.ResolvePinned(root, dependencies)` consumes immutable [validated documents](engine-document-contract.md) supplied by its caller. It performs no database lookup, current-version resolution, authorization, evaluation or effect. No application caller is registered.

The caller must supply every transitively referenced exact tenant/automation/version body once, excluding the root from dependencies. All bodies must belong to the root tenant. Missing references, duplicate identities, foreign tenants, unused bodies and zero snapshots return fixed `engine_pinned_graph_invalid` with no partial graph. Resolution never substitutes a current version when a pinned version is missing. A future tenant store must load these bodies through its authorized immutable scope and prove that each stored version ID still identifies that exact body. Supplying a structurally valid tenant UUID does not establish ownership.

Resolution traverses every branch and pinned body, refusing cross-version cycles. It applies the local depth-16 and expanded-step-100 bounds across document boundaries. Each preset invocation counts as one step plus the invoked target's complete cost. Sequential/all children sum, weighted-random/condition/switch branches take their largest possible path, and finite loops multiply expanded child cost. Shared targets are analyzed once but charged at each invocation; memoization cannot reduce repeated execution cost. Runtime accounting and authorization remain necessary when an evaluator is added.

A graph retains at most 16 versions including its root and at most 256 KiB of canonical document bytes in total. Existing per-document 64 KiB, text, node and loop bounds remain enforced by `Validated`. The byte bound describes retained document text, not an exact Go heap ceiling or throughput guarantee. Temporary node maps and measurement metadata are bounded by version and local-node limits. There are no callbacks, goroutines, shared mutable registries or provider dependencies.

`PinnedGraph` exposes its immutable root, copied version/capability slices, worst-case depth/steps and digest. Each document remains immutable through its copy-returning accessors. `Capabilities()` returns the sorted union of all declared capabilities in the resolved versions, including declarations on branches or documents not selected at runtime. A declaration is not a grant; future admission and execution must recheck current membership, entitlement, provider consent and capability permissions. Do not authorize only from the root document when dependencies declare additional capabilities.

The graph digest binds root tenant/automation/version/digest and a sorted list of every supplied automation/version/body digest, under `overlaid.engine.pinned.v1`. Input dependency order does not matter. Changing a supplied dependency body under the same version IDs changes the graph digest; a future store must independently reject that mutation rather than treating its new identity as permission to publish or retry.

`PinnedGraph.RunID(occurrence, mode)` binds the existing root-document run identity and complete graph digest under `overlaid.engine.pinned-run.v1`. `execute`, `reproduce` and `current_config` remain distinct. Zero graphs, invalid occurrences and unsupported modes return `engine_identity_invalid`. Existing `Validated.RunID` behavior is unchanged, but that local identity alone does not bind dependency bodies. Future complete-graph run admission must use the graph identity and its immutable saved references. Neither identity reserves a run, renews a deadline, grants an effect claim or permits replay after uncertainty.

Documents may contain private action arguments. The digest and budget metadata are separate from raw version bodies; do not log/export `Versions()` contents as metadata. A future persistence unit must define forced RLS, exact composite references, actor/diff publication, current-pointer conflict checks, deletion/retention, populated upgrade/rollback and atomic run/reservation behavior. This pure unit adds no tables or migration number and does not close E2 or Phase #25.

Fixtures cover exact reference matching, missing/duplicate/foreign/unused bodies, cross-version cycles, immutable copies, sorted capability union, dependency-order stability and body-bound identities. Budget checks include 100 allowed steps versus 101 refused, repeated invocations, loop expansion, mutually exclusive branch maxima, exact depth 16, excessive version count and aggregate document size. Concurrent read races and `FuzzPinnedGraph` exercise bounded chains, wrapping and cycle refusal; the existing parser fuzz target covers document input. Run focused package races/lint, bounded fuzzing and `make verify`. These results do not prove persistence, execution, provider acceptance or full feature parity.
