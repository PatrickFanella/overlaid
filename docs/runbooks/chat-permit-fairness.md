# Tenant turns at chat permit admission

Tracking: [#113](https://git.subcult.tv/subculture-collective/overlaid/issues/113), part of P2.2 under [#24](https://git.subcult.tv/subculture-collective/overlaid/issues/24).

[Fair River leasing](tenant-fair-leasing.md) orders ready jobs, but concurrent workers can still race for the same sender permit. `chatpacing.AcquireFair` retains bounded waiting actions and tenant turns under the existing pacing admission lock. The explicit outbound executor supplies its canonical retained tenant, action and original ledger deadline after fresh authorization. No worker or pacing pool is registered at application startup.

Migration `0024_chat_permit_turns.sql` adds a default-empty `fair_state` JSONB column to the existing restricted account table. It changes no role grants, budgets, cooldowns or lease fences. The column has an object/128 KiB storage bound; construction requires the non-null JSONB column. The current writer uses version two with caller eligibility; it reads version-one state for safe lazy upgrade. Runtime decoding rejects unknown versions/fields, invalid hashes, duplicate actions/tickets, missing tenant references, oversized arrays and counter overflow. Existing account/channel capacity limits remain.

Each sender retains at most 256 action entries and 128 tenant entries. Action entries contain only context-separated tenant/action/channel hashes, a monotonic ticket, the original deadline and a granted flag. Tenant entries contain a hash, last grant turn and expiry. Deadlines must still be future and at most two minutes ahead of the database clock. A repeated retained action must preserve its channel and exact deadline. The executor independently reconstructs and checks its canonical ledger deadline; this bounded store is not an indefinite action identity registry.

Admission prunes expired entries in memory, registers new work and considers only ungranted actions with currently eligible channels. The tenant with the oldest grant turn wins; its earliest eligible ticket breaks ties. New tenants enter at the current counter. A grant updates its tenant turn, granted marker, charged attempt and private permit fence in one transaction. Denials retain waiting metadata but reserve no future slot and charge no attempt. They return a poll hint no later than one second or the original deadline, so early completions do not force every contender to sleep for the full abandoned-lease bound. The existing worker caps all preparation retries/snoozes by that deadline.

A granted marker remains through its original deadline. Duplicate concurrent callers cannot take another permit after completion. If storage fails before the executor obtains its action claim, detached `CompleteUnclaimed` removes that marker only under the exact live permit fence, retaining the charged attempt, spacing and tenant turn. A subsequent retry reconstructs the ledger again. A committed or uncertain claim remains protected by the ledger's one-use start; this method grants no provider replay permission. Normal completion retains the marker, including rejected/uncertain outcomes. Failed completion preserves the fence and marker conservatively.

The legacy `Acquire` method rejects an account once fair state is present. Stop older explicit clients before switching: older binaries do not inspect this column. Do not mix client versions or clear fair state to bypass turns. Ordinary one-day inactive account pruning still applies after all two-minute action/turn history is inactive. Keep existing budget/fence state across rollback; additive migration rollback needs no data deletion. An application rollback must stop fair clients first and preserve all action claims and uncertain outcomes. Version-one readers reject version-two fair rows; restore a version-two-capable build to resume, preserving the rows.

`Inspect` remains read-only and reports the same budget, spacing and cooldown metadata. An account in fair mode reports `fair_admission_required`, warns `tenant_turn_unqualified` and returns ready=false: a sender/channel-only probe cannot qualify a particular tenant/action turn. Its retry/deadline metrics describe pacing budgets, not the unknown queue wait. It exposes no hashes, action identities or queue contents and neither registers nor prunes a waiter.

Fairness applies to registered, channel-eligible work whose callers retry before their deadlines. A [three-second caller eligibility lease](fair-admission-liveness.md) lets active callers progress after a selected caller stops retrying; rejoining preserves the original ticket, turn and deadline. Bounded admission can reject additional tenants/actions; it does not guarantee service under unlimited hostile identities or prove the 1,000-channel acceptance target. [Moderation fair permits](moderation-permit-fairness.md) use the shared turn codec with a paired resource binding; cross-lane/provider quota accounting and opt-in registry cutover remain separate work.

Disposable PostgreSQL fixtures exercise competing pools, restart, alternating grants across two tenants, duplicate callers, blocked permits, no-charge denials, read-only inspection, immutable deadlines/channels, cancellation, expired callers, durable capacity, malformed state, migration readiness, transaction rollback and detached pre-claim cleanup. An executor fixture injects a claim-storage failure, proves no provider callback ran, then verifies one successful retry and no replay. Shared `internal/permitturns` state tests cover noisy tenant turns, blocked channels, counter overflow, bounds and malformed state. Synthetic time edits isolate expiry/spacing behavior; they do not measure natural throughput. Run `GOTOOLCHAIN=go1.26.0 bash scripts/ci-postgres.sh` for make verify and both uncached race suites. No fixture sends a live provider message or changes production grants.
