Tracking: [#24](https://git.subcult.tv/subculture-collective/overlaid/issues/24). Contract: ADR 0004. Start from main `dc13188`, after Newsroom PR #49.

Seventeen bounded units (#50–82, even numbers) are closed through merged PRs #51–83. Contracts, atomic retained chat, opt-in registry dispatch, bot stores/onboarding/consent, typed delivery, outbound ledger/jobs, durable pacing, executor, restricted worker and broadcaster/own-bot authorization are implemented. Outbound worker/adapter registration remains off at application startup.

The [remaining-work roadmap](2026-10-15-remaining-work-roadmap.md#next-twitch-implementation-units--24) records P2.1–P2.6. P2.1 is implemented under [#85](https://git.subcult.tv/subculture-collective/overlaid/issues/85) for review, with [restricted shared execution](../../runbooks/shared-bot-execution.md). Priority/warnings, opt-in cutover, normalized-event expansion, conduits and onboarding acceptance follow. The numbered sequence below records implementation history and retained contracts; completed units are not new work.

## Implementation sequence and retained contracts

The existing Twitch user-token WebSocket remains the active transport during migration. Each unit must preserve current commands, moderation, Newsroom lifecycle handling and overlay projection until its replacement has executable compatibility evidence.

1. **Chat and capability contracts — #50.** Add the adapter interface, explicit delivery outcomes, a versioned capability registry and a typed chat envelope. Identity uses tenant, connection, platform, kind and native delivery identity; receipt time never changes it. Twitch chat mapping consumes the typed payload while retaining existing display and moderation fields. Verify redelivery identity, tenant separation, invalid inputs, capability intersections and existing Twitch tests, then `make verify`.
2. **Transactional ingest.** First complete the pinned River transaction compatibility gate under [#52](https://git.subcult.tv/subculture-collective/overlaid/issues/52), as required by ADR 0007. The [isolated spike](../../../backend/spikes/river/README.md) tests the database/sql driver model and forced tenant policies without starting workers. Then create a bounded implementation issue for the production transaction bridge, forced-RLS event storage and atomic River scheduling, with unique tenant/connection/idempotency keys. Include restricted raw-payload retention and viewer deletion. Test concurrent duplicate delivery, rollback and two-tenant isolation using the disposable PostgreSQL harness. Stable identity from unit 1 alone does not suppress duplicate commands.
3. **Twitch adapter migration.** Create an issue for the normalized-event consumer and legacy projection bridge. Preserve current command/moderation semantics, echo suppression and Newsroom lifecycle fencing. Expand typed event kinds with representative native fixtures before enabling subscriptions.
4. **Bot identity and onboarding.** [#60](https://git.subcult.tv/subculture-collective/overlaid/issues/60) adds the [tenant-owned vault store and explicit broadcaster bindings](../../runbooks/bot-accounts.md), with owner checks, refresh serialization and revocation. This foundation enables no OAuth route or sender switch. [#62](https://git.subcult.tv/subculture-collective/overlaid/issues/62) adds the [separate administrative vault for shared service identities](../../runbooks/service-bot-vault.md). [#64](https://git.subcult.tv/subculture-collective/overlaid/issues/64) adds [explicit publication and scoped tenant consent](../../runbooks/shared-bot-delegation.md). [#66](https://git.subcult.tv/subculture-collective/overlaid/issues/66) adds [tenant bot OAuth and Chat identity/consent controls](../../runbooks/bot-onboarding.md). [#68](https://git.subcult.tv/subculture-collective/overlaid/issues/68) adds the [restricted service bot administration/OAuth CLI](../../runbooks/service-bot-admin.md). [#70](https://git.subcult.tv/subculture-collective/overlaid/issues/70) introduces [typed delivery receipts in the existing broadcaster send path](../../runbooks/twitch-delivery.md), with bounded requests and explicit uncertainty. [#72](https://git.subcult.tv/subculture-collective/overlaid/issues/72) adds the [retained outbound action and fenced receipt store](../../runbooks/platform-outbound.md) without executor activation. [#82](https://git.subcult.tv/subculture-collective/overlaid/issues/82) adds [broadcaster and tenant-owned bot authorization](../../runbooks/tenant-outbound-auth.md), fresh token/role checks and durable selection generations, without startup activation. [#85](https://git.subcult.tv/subculture-collective/overlaid/issues/85) adds [restricted shared service-vault execution](../../runbooks/shared-bot-execution.md) with exact publication/consent checks, refresh-only privileges and bounded atomic refresh receipts. Next add moderation priority, then activate bot identities with fresh role/capability checks and restricted shared-vault execution. Keep existing broadcaster authorization recoverable. Real bot account naming and grants require operator input; use synthetic credentials in tests.
5. **Outbound queue.** Add account/channel pacing, moderation priority, retry-after handling and uncertain receipts. Persist action identity and make ambiguous provider delivery explicit. Verify a 1,000-channel simulation without sending provider messages.
6. **Conduit workers and subscriptions.** Add app-authorized conduit reconciliation and worker-owned WebSocket shards after durable ingestion and bot identity are ready. Prove shard recovery and tenant subscription isolation before replacing the current transport.
7. **Desk onboarding and acceptance.** Connect platform, request feature grants, inspect bot role and explicitly test messaging. Complete the phase's two-minute onboarding and simulated-load exit criteria. Live Twitch acceptance remains #39; OBS and release gates remain #40 and #42.
