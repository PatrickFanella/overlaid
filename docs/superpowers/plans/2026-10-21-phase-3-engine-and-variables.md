E1 is the first code unit. It may contain typed contracts and pure validation/identity tests only. Persistence, authorization callbacks, provider adapters, queues and dispatcher selection are separate units. A valid document means structurally acceptable input; it grants no current permission, effect claim or pacing permit. The structural validator rejects local preset-reference cycles; E2/E5 must resolve pinned saved versions inside the tenant boundary before validating the complete graph.

## Budgets and policy gates

Use the ADR values as initial acceptance bounds, not measured throughput claims:

- Engine: depth 16, 100 evaluated effect steps, 20 loop iterations, at most four explicitly permitted concurrent effects and 30 seconds active computation. Validation must account for worst-case loop/tree expansion; runtime accounting still stops dynamic exhaustion. Long-delay elapsed time is distinct from active computation and must retain an explicit original source/continuation deadline.
- Variables: 4 KiB source, depth 16, 256 AST nodes, 100 resolution steps, 8 KiB output and one-second ordinary rendering. Apply platform chat truncation separately. Use byte/rune units explicitly in types, diagnostics and tests.
- HTTP variables: proposed two requests, 64 KiB bodies, three validated redirects, two seconds per request within a three-second external budget, plus current plan reservations. Pure parsing/rehearsal does not open this path. Resolve captured values during replay; do not query today's provider state.
- Eval: disabled in hosted and default self-host operation. No in-process fallback. A later launcher must prove bounded child-process input/output, kill/reap deadlines, OS memory/process limits, no network and minimal read-only filesystem before a separate activation review. A Go memory target alone is insufficient.

Live state, follow/account age, viewer count and stream limits need typed freshness/availability rules at their consuming unit. Unknown, disconnected, stale and false are distinct values. Do not convert the last observed stream event into an affirmative current permission or restriction result. Mandatory authorization and current entitlement remain independent of all/any/none restriction predicates.

## Identity, privacy and durable effects

Version/configuration identity is separate from effect permission. Pin source, automation version, node and original effect occurrence when admitting work. Repeated admission may return an existing action; it cannot create a fresh request key, renew a deadline or repeat an effect after a claim. A completed engine step records its linked outbound outcome; it must not treat a timeout, uncertain result or missing delivery receipt as permission to replay. Moderation retains its separate typed receipt validator and capacity lane.

Run snapshots contain only the bounded product projection needed for deterministic evaluation. Do not copy native provider payloads, credentials, authentication headers or unrestricted request context into traces. Define fixed error codes and per-field redaction before persistence. Raw variable values that may contain personal text belong to scoped retained input, not general logs or public exports. Event/viewer/member/tenant deletion must remove or invalidate dependent captured input, runs and continuations according to the owning lifecycle policy. Metadata-only export is not permission to retain deleted private content through a reference.

Every persistence issue must document exact roles, policies, indexes, cascades and runtime compatibility guards before selecting a migration number. Use the repository's next real migration number at implementation time. Existing queue roles and vault pools do not gain blanket access to engine tables. No unit adds a second command dispatcher or broadens provider budgets.

## Migration and rollback

1. Inventory actual saved behavior and capture effect-free old/new fixture outputs. Include commands, Newsroom actions, timers, reward rules, quick actions, missing values and API/now-playing inputs. Record each catalogue item as covered, intentionally different or missing; passing the initial command set does not close #26/#27.
2. Publish immutable converted versions beside original settings and keep stable source mappings. Preview cannot mutate provider state, counters, cooldowns or live selection. A preview difference needs explicit selection rather than silently changing syntax.
3. Switch one source under a transaction/owner fence that drains or refuses the old path. Recheck saved revision and runtime ownership before selection. Failed new admission cannot fall back to the legacy handler.
4. Pin in-flight runs to their original versions. On rollback, stop new engine leasing/selection as required, retain claims/receipts/reservations and original source mappings, and preserve the schema compatibility guard. Never restart an incompatible binary or requeue uncertain effects as legacy work.
5. Remove a legacy dispatcher only after its complete migration fixture set and runtime ownership checks pass. File-mode support requires an explicit bounded persistence/selection design before engine activation there; this plan does not silently remove existing self-host behavior.
